# Closed-trade receipt and Markets discovery (v1)

Status: **design ready; UX changed no app files.** This document is the implementation spec for two
surfaces that are still incomplete in v1.1:

1. the **receipt** shown when a trade is closed (desktop dialog + mobile detail), and
2. the **discovery feed** (`/markets`) with New pairs, Graduated and Trending.

Scope: `docs/design` only. Token values stay at `app_tokens.dart` 0.3.4 (sha256 `5043960a…7f06417f`),
paper-only, no secrets, no deploy. The copy catalogue in `packages/i18n` is generated by UX; do not
hand-edit `en.json`, `id.json` or the ARB files.

Related: [`pnl-report.md`](pnl-report.md) (shipped PnL behaviour), `packages/contracts/src/wire/events.ts`
(`PositionWire`, `PnlSummary`), and the Markets v1 design source in the UX design workspace
(`ux/MARKETS_v1.md`).

## Non-negotiables

| rule | meaning |
|---|---|
| Server numbers only | The client never derives PnL, PnL %, hold, fees or prices. If the server omits a value, the UI shows `—`. |
| Null is not zero | `null` renders `—`; a reported `0` renders `0` in a neutral tone (no green, no arrow, no `+`). |
| No fake columns | A discovery column renders only when the response says the capability exists. Never render a column that is null for every row. |
| One target per row | A market row, and a receipt action, is the only click target. No nested links or buy buttons inside a row. |
| Receipt is read-only | No Sell, Pause, Stop, Share, Copy or transaction CTA on a closed trade. |
| Mode-less markets | `/markets` is market-wide data. It is not Paper/Real and must not reuse the per-strategy `/coins` screener. |

# Part A — Closed-trade receipt

## A1. Surfaces

| platform | surface | entry | v1 state |
|---|---|---|---|
| Desktop | `PnlReportDialog` → receipt view | click or `Enter` on a closed ledger row | **new**; ledger stays, receipt opens inside the same 760 px dialog |
| Mobile | Position detail, closed branch (`_ClosedReceipt`) | tap a closed row in Positions | **exists**; field order, units, provenance and server-only values need the fixes below |
| Web | `/pnl` ledger | row already shows In / Out / Fees / entry→exit | parity only; labels and null rules must match this doc |

Code anchors: `apps/desktop/src/components/PnlReportDialog.tsx`,
`apps/mobile/lib/features/positions/positions_screen.dart` (`_ClosedReceipt`).

The receipt is for a **fully closed position** (`status = closed`). An open position with partial
takes keeps its live exit ladder and never renders this receipt.

## A2. Field order (both platforms)

This order is fixed. A null field keeps its row and shows `—`; it is never removed from the receipt.

Notes:

- `pnl = sol_out − sol_in`, already computed by the server. Fees are **context**, already inside
  `sol_in`/`sol_out`; never subtract them again and never show "Net PnL".
- Entry/exit prices are shown in **SOL**, not USD. `PositionWire` has `avg_entry_price_sol` and
  `exit_price_sol` but no USD price; converting on the client would contradict the provenance line.
  A USD reference can be added later only when the server sends `*_price_usd` with an `as_of`.
- The unit line carries the unit once. Do not repeat "paper SOL" in all four breakdown values.
- #12 and #13 share one `Entry → exit` label: the price is the first line, the time is the second.
  The identity keeps the separate close time (A2 #5); do not print `Entry → exit` twice.

## A3. Desktop layout (`PnlReportDialog`)

The dialog is 760 px wide (`min(760px, 92vw)`). A side-by-side receipt would squeeze the ledger, so
v1 uses a **drill-down inside the same dialog**:

- Ledger row is a button (`Enter`/`Space`); selecting it replaces the dialog body with the receipt.
- Header becomes: `← Closed trade` (back), `$SYMBOL` as subtitle, existing `×` close.
- Body max-width 560 px, 16 px padding, 12/16 px section gaps, 1 px `border.subtle` dividers.
- Breakdown is a 2×2 grid: SOL in / SOL out on row 1, Fees / Hold on row 2.
- `View bot` is right-aligned at the bottom; it closes the dialog and opens the bot/strategy screen.
- `Esc` behaviour: receipt open → back to the ledger; ledger open → close the dialog.
- Returning to the ledger restores range, sort, bot filter, scroll offset and keyboard focus.
- Wide dialogs (≥ 1040 px) may later use a right-side inspector; not in v1.

## A4. Mobile layout

One scroll page inside the existing closed position detail; no new route, no sticky action bar.

- App bar: back + `Closed trade`; the position's `ModeChip` stays in the identity row.
- Content padding 16; sections use 1 px dividers and 12/16 gaps.
- Identity: 32 px logo, `$SYMBOL`, bot, `Closed` chip, close time.
- Headline: label `Realized PnL` + hint `Locked at close…`; value 24 mono; `%` under it.
- Breakdown: 2×2 grid; long ID labels wrap, never truncate to "Biaya (dila…".
- Entry→exit price and time stack on narrow widths; the arrow stays on one line.
- Reason block: label + one-line explanation.
- Unit line, provenance, then `View bot` as a 44 pt secondary button (full width).
- Back returns to Positions with the previous scroll offset and focus.
- Dark and light parity; no colour-only meaning.

## A6. Formatting rules

- **Money**: format lamports with the shared formatter; 3–4 decimals; locale decimal separator; minus
  is U+2212. The headline shows the number only; the unit appears once in the A2 #15 line. Breakdown
  values are numeric only.
- **Percent**: one decimal, sign always (`+31.0%`, `−12.5%`), zero `0.0%`. Never derive from cost when
  `pnl_pct` is null; show `—`.
- **Price**: SOL, up to 9 significant digits, no exponent, trailing zeros trimmed
  (`0.000000255`, not `2.55e-7`); a real zero is `0 SOL`. The `{entry}`/`{exit}` price placeholders
  are the fully formatted values including the `SOL` unit; never append a unit in the component.
- **Hold**: derive text from `hold_seconds` only. `45s`, `19m`, `2h 5m`; never compute from
  `closed_at − opened_at` and never show `0s` for a missing value.
- **Time**: WIB (GMT+7), 24-hour `HH:mm`. Close time always carries the date. Entry→exit carries dates
  only when the exit falls on a different WIB day; then both sides carry dates. Year only when it is
  not the current year.
- **A11y**: `—` carries the `common.value.unavailable` label; PnL and % are text, not colour-only;
  focus order is back/close → `View bot`.

## A7. Null, zero, logo, provenance

- **Null → `—`**, with the row kept. Never `null`, `0`, `0.00` or a blank. A hyphen `-` is not the
  dash; use U+2014.
- **Zero is a value**: `0.000`, `0.0%`, `0s`; neutral text colour, no `+`, no arrow. A zero PnL is not
  a win and not a loss.
- **PnL null**: do not compute `sol_out − sol_in` on the client. `pnl_pct` null: do not compute a
  ratio.
- **Fees**: reported context; already inside in/out. Null → `—`.
- **Logo**: proxy URL with `logo_hash`/`logo_url`; identicon from `mint` when either is missing. Never
  render an untrusted `image` URL, never leave the slot empty.
- **Provenance**: the line is true only if every displayed number is server-reported. If a value is
  derived, fix the value; do not soften the line.

## A9. Actions

- Only `View bot`, secondary. Rendered only when `strategy_id` resolves to a known strategy.
- Desktop: closes the dialog and opens the bot; focus returns to the invoking control when the user
  comes back.
- Mobile: pushes the bot/strategy screen; back returns to the receipt, then to Positions.
- Forbidden on a closed trade: Sell, Pause, Stop, Star, Share, Copy, "View transaction".

## A10. Platform mapping gaps (no backend change required)

Desktop `ClosedTradeView` is an app-local view type, not the wire. Backend
`GET /positions?state=closed` already returns `PositionWire`; extend the adapter/type with:

| field | source | use |
|---|---|---|
| `strategy_id` | `PositionWire.strategy_id` | Bot name, `View bot` |
| `sol_in_lamports` | `PositionWire.sol_in_lamports` | SOL in |
| `fees_lamports` | `PositionWire.fees_lamports` | Fees (reported) |
| `avg_entry_price_sol` | `PositionWire.avg_entry_price_sol` | Entry price |
| `exit_price_sol` | `PositionWire.exit_price_sol` | Exit price |
| `opened_at` | `PositionWire.opened_at` | Entry time |
| `logo_url` | `PositionWire.logo_url` | Logo fallback |

Mobile already has cost/proceeds/fees/exit reason/opened/closed and the logo; it does **not** yet carry
`hold_seconds` or the SOL entry/exit prices. Two corrections:

1. Add `hold_seconds` to the view model and use it, with `pnl_lamports` and `pnl_pct` directly; do
   not fall back to `holdAt(now)`, `proceeds − cost` or `pnl / cost` for a closed trade.
2. Add `entry_price_sol` / `exit_price_sol` to the position view model and map
   `avg_entry_price_sol` / `exit_price_sol`. Do not reuse the USD `entryPriceUsd` /
   `exitPriceUsd` fields for the receipt.

Bot name: resolve `strategy_id` through the strategies map. If it is unknown, show `—` and hide
`View bot`; never print the raw UUID (mobile currently falls back to `strategyId`).

`symbol` is not on `PositionWire`. v1 falls back to the short mint (plus identicon), which is honest.
An optional 1.1.7 additive `symbol`/`name` on `PositionWire` would remove the fallback; it is not a
blocker.

## A11. Acceptance criteria (receipt, G10)

1. Desktop dialog and mobile detail show the A2 order with the A5 labels.
2. Every A2 field is present even when null; null renders `—` and is announced as unavailable.
3. A real zero renders `0.000` / `0.0%` / `0s` in neutral text, with no `+`, arrow or colour.
4. PnL and % carry an explicit sign; `arrow: false`; the unit line is shown once.
5. `pnl_lamports`, `pnl_pct` and `hold_seconds` are the server values; no client recomputation in the
   receipt path (unit test with a locked value different from `proceeds − cost`).
6. Entry/exit prices read `avg_entry_price_sol` / `exit_price_sol`; a missing side shows `—`.
7. Times are WIB; entry→exit dates appear only when the exit crosses midnight; close time is dated.
8. The exit reason is localized, has its one-line explanation, and an unknown code falls back to
   `Closed` without leaking the enum.
9. The provenance line is present and the only action is `View bot` (or no action when the bot is
   unknown).
10. A logo or deterministic identicon is always present; no empty avatar.
11. Desktop: row → receipt → back preserves range, sort, filter, scroll and focus; `Esc` goes back
    before closing. Mobile: back returns to the previous scroll position.
12. EN and ID are complete on both platforms; no hardcoded copy; `ci_check_vendored.sh` stays green.

# Part B — Discovery feed v1 (`/markets`)

## B1. Information architecture

| platform | route | entry | nav change |
|---|---|---|---|
| Web | `/markets?tab=trending\|new\|graduated&window=` | nav **Markets** (compass), after Activity | +1 item; `/coins` remains the per-strategy screener |
| Mobile | `/markets` (child of the Home branch) | Home **Markets** section: 3 chips + top 5 rows + `See all` | no new bottom tab |
| Desktop | `markets` view | nav **Markets** (compass) | +1 nav item |

Why a separate surface: screener rows are per strategy and carry mode; market rows are market-wide,
mode-less and come from a feed. Mixing them makes the mode chip meaningless.

## B2. Tabs

Exactly three, in this order, default **Trending**. No watchlist, no filters by socials in v1.

| tab | includes | sort | default window | window options | cap / paging | columns |
|---|---|---|---|---|---|---|
| **Trending** | all mints with a rank in the window | `rank_position` asc (server order) | 1h | 5m · 1h · 24h | top 100, no paging | rank, coin, age (or graduated age), venue, mcap, change*, activity, guard |
| **New pairs** | `first_seen_at >= now − window`, one row per mint (even if it migrated since) | `first_seen_at` desc | 1h | 15m · 1h · 6h · 24h | 200 cap, keyset 50 | coin, age, venue, mcap, change*, activity, guard |
| **Graduated** | `migrated_at != null` and `migrated_at >= now − window` | `migrated_at` desc | 24h | 15m · 1h · 6h · 24h | keyset 50 | coin, graduated age, venue (AMM), mcap, change†, activity, guard |

`*` Change is rendered only when the response capability says the price-history field exists.
`†` Graduated change is **since migration** (`price_change_since_migration_pct`), not the 24h change;
if that field is absent, Graduated ships without a change column.
`activity` is our screening-event count, not market trades.

Rules:

- One row per mint **within a tab**. `first_seen_at` is the earliest observation, not the latest.
- A mint first seen in the window and migrated since stays in New pairs with the `AMM` venue chip.
  The same mint can legitimately appear in both New pairs and Graduated, because the tabs are two
  views of the same market, not one merged list.
- Tab counts come from the server's `total_count` for the window, capped display `99+`. Never count
  loaded pages.
- New pairs rows younger than 60 s get an outline `New` chip. Age already says "new"; the chip is an
  extra scan cue, not a colour fill.
- Any tab, window or filter change **discards the cursor** and refetches page 1. Never carry a keyset
  cursor across filters (the PnL cursor bug class).
- Paging is an explicit `Load more` button (44 pt mobile, 32 px web/desktop), not infinite scroll.
  New live rows are buffered while the list is scrolled (B7).

## B3. Metrics matrix

| column | source field | Trending | New | Graduated | when null | rule |
|---|---|---|---|---|---|---|
| rank | `rank_position` | ✓ | — | — | server must assign | 1–100, left-aligned mono; never client-sorted |
| coin | `mint`, `symbol`, `name`, `logo_hash`, `logo_url` | ✓ | ✓ | ✓ | symbol → short mint; logo → identicon | escaped untrusted text; never a remote image |
| age | `first_seen_at` | ✓ | ✓ | — | `—` | monospace, `2m`, `1h 04m`, `3d` |
| graduated age | `migrated_at` | — | — | ✓ | `—` | header `Graduated`, not `Age` |
| venue | `venue`, `mcap_source` | ✓ | ✓ | ✓ | `—` | `Curve` / `AMM` neutral chip |
| mcap | `mcap_usd`, `market_cap_lamports`, `mcap_source`, `mcap_as_of` | ✓ | ✓ | ✓ | `—` (both null) | `$412K`; `≈` only when `mcap_source = curve`; SOL hint |
| change | `price_change_{window}_pct` (New/Trending), `price_change_since_migration_pct` (Graduated) | ✓* | ✓* | ✓† | `—` per row | sign + colour; zero neutral; capability-gated per tab |
| activity | `activity_count_window` | ✓ | ✓ | ✓ | `—` | our screening events, tooltip says so |
| guard | `guard_verdict`, `guard_score` | ✓ | ✓ | ✓ | `—` + "not evaluated" hint | `Passed 82` / `Guard failed` / `—`; never "failed" when unscored |
| launchpad | `launchpad` | filter only | filter only | filter only | filter hidden | not a column in v1 |

Column presence is decided by the response `capabilities` object (B11), not by sampling the visible
page. A column that is null for every visible row must not render. If the backend cannot supply
change/volume/liquidity/holders yet, the screen ships with fewer columns.

If `capabilities` is missing entirely (older backend), render only the guaranteed set — coin, age,
venue, mcap, guard, and activity when present — and never guess at change or volume.

Responsive priority: at ≤ 1280 px drop `activity` first, then `change`; at ≤ 1024 px keep coin, age,
mcap and guard, and move venue/change/activity into the row's accessible name and the coin detail.
Never clip a header or a value, and never require horizontal scrolling on the feed.

Mcap detail:

- `mcap_usd` present → USD primary, `market_cap_lamports` as the SOL hint (`≈ 2,290 SOL`).
- `mcap_usd` null but SOL present → show SOL only; no `$` and no invented rate.
- `mcap_source = curve` → prefix `≈` (indicative) and tooltip `As of {time}` from `mcap_as_of`.
- `mcap_source = amm` → no `≈`; still show `as_of` in the tooltip.
- Both null → `—`.

Change detail:

- Render only when the response's `capabilities.change_pct` (for the active tab) is true; the column
  is absent otherwise, so no empty column and no sorting by a field we do not have.
- Graduated uses `price_change_since_migration_pct`; if the capability is false, no change column.
- `+38.4%` in profit colour, `−12.5%` in loss colour, `0.0%` in `text.secondary`. Sign always;
  colour never alone.
- Per-row null → `—`; a zero is a real zero.

## B4. Row anatomy

Shared semantic row, platform-specific density:

| slot | content | rule |
|---|---|---|
| avatar | proxy logo / identicon | 32 mobile, 24 web, 22 desktop; never empty |
| symbol + name | `$MOON` 13/600 + name 10 `text.tertiary` | one line, truncated; symbol escaped |
| age | `2m`, `1h 04m`, `3d` | from server timestamps; Graduated uses `migrated_at` |
| venue | `Curve` / `AMM` chip | AMM uses `brand.onBrandContainer`; neutral otherwise |
| mcap | `$412K` + SOL hint | `≈` only for curve; see B3 |
| change | `+38.4%` | only if capability exists; sign + colour |
| activity | count in window | optional column; tooltip explains it is our screening events |
| guard | `Passed 82` / `Guard failed` / `—` | text, not a nested link; the row is the only target |
| rank | `1`–`100` | Trending only; mono, left aligned |

- **Web/desktop**: dense list/table, Comfortable 40 px / Compact 36 px, 1 px row dividers, sticky
  header with the tab bar. No card grid.
- **Mobile**: 68 pt card, two lines. Line 1: avatar + `$SYM` + age + mcap. Line 2: venue + change
  (if available) + guard. `activity` is not shown on the 68 pt card in v1; it stays in the coin
  detail so the card does not wrap on a 360 px screen.
- Row action: `Review` → coin detail. No Buy, Sell, Star or one-tap ape.
- Focus: visible 2 px `border.focus`; `Enter` opens; `J`/`K` moves on desktop; focus stays on the
  same mint if the list re-sorts.
- Numbers are mono tabular and right-aligned; rank is left-aligned mono.

## B5. Trending disclosure

The score is a documented composite, not a volume leaderboard:

```
score = w1 * mcap_growth_in_window
      + w2 * activity_count_window       (our screening events)
      + w3 * migrated_in_window          (1 if migrated_at is inside the window)
```

- Weights are server-owned and versioned. The response returns `rank_position`, `rank_score`,
  `weights_version`, the weights and the per-row inputs so QA can recompute the order.
- The UI never displays `rank_score` as a number; it displays the rank and this caption under the
  tab bar (2 lines, 10–11 `text.tertiary`):
  `Ranked by market-cap growth, screening activity and recent migration. No trade-volume data yet.`
- When volume/liquidity land, the caption and the score change together in one release. Never change
  the ordering silently under the same label.
- Rank changes ≥ 10 places between polls get no animation in v1 (motion on a live list is noise and
  hurts screen readers).

## B6. States

| state | trigger | list | header / banner | action |
|---|---|---|---|---|
| Loading, first paint | no cached rows for this tab/window | 8 row skeletons; tab counts `—`; no in-table spinner | `Updated —` | none |
| Loading, tab switch with cache | cached rows for that tab/window | keep rows, subtle progress line; no layout jump | previous `Updated {age}` until the response lands | none |
| Empty, New | zero rows in window | icon + `No new pairs in the last {range}` | tabs normal | `Widen to 24h` if window < 24h, else `Refresh` |
| Empty, Graduated | zero rows in window | icon + `No graduations in the last {range}` | tabs normal | `Widen to 24h` if window < 24h, else `Refresh` |
| Empty, Trending | no rankable rows | `Not enough data to rank yet`, no list | tabs normal | `Refresh` |
| First-load error | no cached rows; request failed | full-panel error + one retry | `Markets could not be loaded` | `Retry` |
| Feed down with rows | refresh failed; rows exist | rows stay, each age goes `stale` | banner `Live feed offline · showing last data from {time}` | `Retry` |
| Rate-limited (429) | `retry_after_s` present | rows stay; never clear the table | `Feed rate-limited · retrying in {seconds}s` | auto-retry at 0, no manual loop |
| Offline device | no network | cached rows with their original timestamps | `You're offline · showing cached rows from {time}` | `Retry` when back online |
| Partially stale | a row has not updated for 60 s | per-row stale dot + age colour | screen dot stays `live` | none |
| Guard not evaluated | `guard_verdict = null` | `—` | tooltip `Guard has not scored this coin` | none |
| Not tradeable | `tradeable = false` | hidden by default behind `Show not tradeable`; the chip carries the count, e.g. `Show not tradeable (3)` | filter chip | toggle |

Rules:

- A 429 or error never replaces existing rows with an empty state.
- A refresh failure marks rows stale; it does not delete them.
- Offline cache is per tab/window in memory. A cold start with no cache shows the first-load error,
  not an empty feed.
- The demo/mock build shows the standard `Example data` banner; a live-looking market screen on mock
  data is forbidden.

## B7. Live behaviour

| behaviour | rule |
|---|---|
| Transport | SSE/WS preferred; polling is acceptable for v1 if the response includes `next_poll_ms` and `as_of` |
| Insert | new rows enter at the top with a 120 ms fade; if scrolled > 200 px from the top, buffer and show `{n} new · tap to refresh` instead of inserting above the viewport |
| Apply buffered rows | tap scrolls to top and applies; the pill then disappears |
| Remove | rows never disappear silently; a row that fails 3 polls is marked stale and kept for the window |
| Focus | if a row is focused and the list re-sorts, keep focus on that mint, not the index |
| Age | tick every 10 s locally from server timestamps and `skewFrom(server_now)`; never from client arrival time |
| Header freshness | `Updated {age}` from the newest row's `as_of`/`mcap_as_of`; `live` / `stale` / `offline` dot |
| Background | pause updates after 60 s hidden; on return, one fetch and `Updated now` |
| Render | patch per row; do not re-render the whole table for one cell |
| Announce | inserted rows are announced once per 30 s max: `12 new pairs`; never every tick |
| Optimism | none. A row appears only when the server sends it |

## B8. Deep links and back

- Web: `/markets?tab=trending&window=1h`; `tab=new|graduated` and the tab's valid windows. Unknown tab
  → Trending; invalid/unsupported window → that tab's default. Tab/window changes update the URL with
  `replace` (no history spam); browser back returns to the previous tab/window.
- Mobile: `/markets?tab=graduated` (window may follow). Read the query **before the first frame** and
  also react to later query changes while the screen is open — do not repeat the `/pnl?window=`
  read-once bug.
- Desktop: no URL; remember the last tab/window for the session (not persisted across launches).
- Row → detail → back restores tab, window, scroll offset and focus on the originating row.
- A shared link must open the same tab; no in-memory-only filter state.

## B9. Market-only coin detail

A market coin we never screened has no trail. Tapping its row must not open an empty page.

The detail's market-only state shows:

- logo, `$SYMBOL`, name (escaped), venue chip, launchpad; header context `Markets / $SYMBOL`.
- chart, or `Chart unavailable for this coin yet` — never a fake line.
- mcap (USD + SOL hint, source, `as_of`), first seen, migrated (date or `—`).
- Guard: `Not evaluated` + `Guard has not scored this coin`; never `Guard failed`, never a score.
- tradeable state; not-tradeable treatment is neutral and explains why.
- one primary action: `Send to bot review` → choose a strategy → creates a pick through the existing
  pick/proposal path (the exact endpoint is Backend's; it must not create a buy). On success the
  button becomes disabled `Sent to bot review`; there is no buy action on this screen.
- if the workspace has no strategy: disabled action + `Create a bot to review this coin`.

No empty trail sections, no invented score, no "Example data" inside a real market feed.

## B11. Data request to Backend

Read-only and additive; no contract bump for fields already on `CoinWire`.

```
GET /v1/workspaces/:ws/markets/new?window=15m|1h|6h|24h&limit=50&cursor=
GET /v1/workspaces/:ws/markets/graduated?window=15m|1h|6h|24h&limit=50&cursor=
GET /v1/workspaces/:ws/markets/trending?window=5m|1h|24h&limit=100
GET /v1/workspaces/:ws/markets/:mint/overview
```

Response envelope:

```
rows: MarketRow[]
tab, window
as_of, as_of_seq, next_poll_ms?          // if polling
total_count                              // for the tab count; null = hide count
next_cursor                              // null on the last page
capabilities: {
  change_pct, activity, volume, liquidity, holders, guard, launchpad
}
rank?: { weights_version, weights, inputs }   // Trending only
```

`MarketRow` (all optional fields nullable, never zero-filled):

```
mint, symbol, name, logo_hash, logo_url, launchpad, venue
first_seen_at, migrated_at
market_cap_lamports, mcap_usd, mcap_source, mcap_as_of
price_change_5m_pct, price_change_1h_pct, price_change_24h_pct
price_change_since_migration_pct            // Graduated only
volume_lamports_24h, liquidity_lamports, holders, trades_24h
activity_count_window
guard_verdict, guard_score, tradeable
rank_position, rank_score, rank_inputs        // Trending only
```

Hard requirements:

1. Unknown values are `null`, never `0`. No `0 SOL` volume and no zero-filled holders.
2. `first_seen_at` is the earliest observation; dedupe by mint.
3. `mcap_source` and `mcap_as_of` travel with every mcap so the UI can mark curve values indicative.
4. `capabilities` is authoritative for column rendering. Do not make the client infer a column from a
   page sample.
5. Trending returns `rank_position` in the final order (server breaks ties) plus `weights_version`,
   the weights and the inputs, so QA can recompute it. No volume-based ranking until volume exists.
6. If the transport is polling, return `next_poll_ms`; the client must not invent a cadence.
7. `as_of` comes from the server; clients apply `skewFrom(server_now)` for ages.
8. No fixture rows in a release build. Mock mode shows the standard example-data banner.

Backend must confirm which fields ship in the first slice. UX hides any column whose capability is
false; the screen ships with fewer columns rather than fake ones.

## B12. Acceptance criteria (G11)

1. `/markets` exists on web, mobile and desktop with exactly three tabs — Trending, New pairs,
   Graduated — default Trending.
2. Deep link `?tab=&window=` restores tab and window on web and mobile; no in-memory-only state;
   mobile reacts to later query changes.
3. New pairs sorts by `first_seen_at` desc; Graduated includes only `migrated_at != null` inside the
   window, sorted `migrated_at` desc; Trending returns `rank_position` and discloses its inputs.
4. Rows come from the backend feed; no fixture rows in a release build. With the feed down, a visible
   banner names the last update time.
5. No column renders when its capability is false; unknown values are `null` server-side, not `0`.
6. Every row has a proxy logo or a deterministic identicon; no empty mark.
7. Row action is Review → coin detail. There is no buy/sell/star control on the market surface; a buy
   still goes through Guard + the approval queue.
8. A never-screened mint opens the market-only detail (B9) with chart state, mcap, venue, first seen,
   migrated and Guard "not evaluated"; it never renders an empty trail.
9. Live: insert at top, no focus loss, buffered "N new" when scrolled, `Updated {age}` from server
   timestamps, per-row stale after 60 s, paused when hidden.
10. Empty/error/rate-limited/offline states match B6, each with one clear next action; 429 and refresh
    errors never clear existing rows.
11. Changing tab/window/filter discards the cursor and refetches page 1; tab counts come from
    `total_count`, not loaded rows.
12. All strings are localized EN/ID on all three platforms; no hardcoded copy; contrast ≥ 4.5 text /
    ≥ 3.0 non-text; tabs are a real tablist; rows are keyboard reachable; colour is never the only
    signal.
13. Token pin unchanged (`app_tokens.dart` sha256 `5043960a…7f06417f`); no visual regression on
    Coins/Positions; evidence screenshots for all three tabs, empty, stale, offline and the
    market-only detail, dark + light.
