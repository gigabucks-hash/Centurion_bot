# Security audit — 2026-11-14

Audit of Centurion Trade (local web, Windows desktop, paper API, local MCP) focused on real-money loss: a swap that sends funds to someone else, a limit that can be bypassed, or a signature that can be replayed. Product decisions left as they are: once Real is enabled in the app, the local autotrader may trade and change limits with no second approval; limits have no hard maximum; the installer stays unsigned; the UI does not say Tauri; there is still no transfer to another wallet.

## Critical

| # | Location | Impact | Status |
|---|---|---|---|
| C1 | `apps/desktop/src-tauri/src/real/tx.rs` | Token instructions use a one-byte code. The checker read a 4-byte code, so a normal Transfer, TransferChecked, or CloseAccount did not match and was allowed. A swap response could add a top-level transfer of SOL or tokens to another wallet. | Fixed. The checker reads the one-byte code and refuses any token instruction that can move value unless the destination is the owner or a temporary account this same transaction closes back to the owner. |
| C2 | `apps/desktop/src-tauri/src/real/tx.rs` | System instructions other than Transfer (CreateAccount, TransferWithSeed, Assign, …) were ignored, so lamports could leave the wallet. Approve and SetAuthority were ignored, so a later transaction could pull tokens. Creating an associated-token account for a different wallet spent the owner's rent. | Fixed. Only Transfer (to the owner, a closed temporary account, or a Jito tip under the cap) and a CreateAccount that is closed back to the owner are allowed. Approve, SetAuthority, MintTo, Burn, Freeze, and unknown token instructions are refused. An associated-token account must belong to the owner. |
| C3 | `apps/desktop/src-tauri/src/real/mod.rs`, `commands.rs` `real_prepare_swap` | The Jupiter quote URL interpolated the mint. A mint containing `&` could overwrite `slippageBps`, the output mint, or the amount. The quote body was not checked, so min-out could be 1 lamport and a platform fee could pay a third party. | Fixed. Mints must be base58. The quote's mints, in-amount, slippage, min-out, route, and platform fee are checked before a transaction is shown to the wallet. |
| C4 | `commands.rs` `real_submit` | Any signed transaction the window handed over was broadcast after a vet that used the global tip, which can be higher than the strategy tip. The window could also sign a transaction this app never built. | Fixed. Submit accepts only a transaction prepared by this app in the last two minutes, vets it again at the tighter tip, and records the SOL spend. A failed send rolls the spend back. |

## High

| # | Location | Impact | Status |
|---|---|---|---|
| H1 | Desktop `real/limits.rs`, web `lib/local/real-book.ts` | The enable message and the loosen message had no nonce. The same signature could turn Real back on, or loosen the same limits again, after the owner had tightened or switched Real off. A `real.json` with `enabled: true` and no valid signature was treated as on. | Fixed. Each enable and each loosen gets a fresh nonce. The signature is checked again when the book is loaded. A used signature is rejected. MCP may still loosen with no second signature after Real is on; that path is `applyKnobsDirect` and is unchanged. |
| H2 | `commands.rs` `real_prepare_swap` | Open positions, SOL spent today, and capital in use were whatever the window sent. A modified page could send zeros and skip the daily cap, the capital cap, and the position cap. Two prepares at once could both pass before either was recorded. | Fixed. The app keeps its own spend list and an in-flight hold. The numbers used are the larger of the window's figures and the book's figures, so the window cannot report less than the app has already counted. |
| H3 | `apps/web/mcp/http.ts`, `app/api/local/mcp/route.ts`, `app/api/local/real/route.ts` | The MCP HTTP bearer was compared with `!==`. The HTTP server checked the socket address and not Host or Origin, so a DNS-rebinding page on this PC could reach it. The local Real routes had no Origin check, so another website could POST to `127.0.0.1` and change RPC, strategies, or Real, if the browser sent the request. | Fixed. Bearer compare is constant-time. Host must be loopback. A browser Origin must be loopback. `Sec-Fetch-Site: cross-site` is refused. Node (the MCP process) sends neither Origin nor that header and still works with the bearer. |
| H4 | `apps/desktop/src-tauri/src/real/sign.rs` | The wallet page loaded `@solana/web3.js` from `esm.sh`. A changed copy of that script could alter the transaction before Phantom signed it. The loopback server accepted the first POST with no check that it came from the page. | Fixed. The page is inline, with a content-security policy that blocks remote scripts. The POST must carry a one-time header and a Host of `127.0.0.1:<port>`. A foreign Origin is refused. |
| H5 | `rpc_url_ok` in desktop `limits.rs` and both TypeScript copies | `http://` was allowed when the host *started with* `127.0.0.1` or `localhost`, so `http://127.0.0.1.evil.com` was treated as this PC. `https://169.254.169.254` was allowed. The HTTP client followed redirects, so an RPC URL could bounce to a metadata address. | Fixed. The host must be exactly `127.0.0.1`, `localhost`, or `::1` for plain HTTP. Link-local, unspecified, and multicast literals are refused on HTTPS. Private LAN addresses stay allowed. Swap and send clients do not follow redirects. |

## Medium

| # | Location | Impact | Status |
|---|---|---|---|
| M1 | `apps/web/lib/local/mcp.ts` | Real buys were stored as JavaScript numbers. Adding them and converting back to lamports can round, so a daily or capital cap could be passed or a position left short. Selling the same key twice both returned success. A sell by key was rejected unless a mint was also sent. | Fixed. The ledger stores lamport strings and sold basis points. Caps add with `bigint`. The second sell of a key returns `not_found`. |
| M2 | `apps/web/lib/mock/store.ts` `closePosition` | A partial sell added `remaining * (fraction / 10000)` in floating point, so repeated partial sells could leave a position that never quite reached 100%. | Fixed. The remaining size is basis points and the add is integer division. A 100% sell still closes the position. |
| M3 | `apps/web/mcp/token.ts`, `lib/local/mcp.ts`, `lib/local/real-book.ts` | The token file mode was set only on create. An existing file or a directory created with a loose umask stayed readable by other users of the machine. | Fixed. The directory is mode `0700` and the token and `real.json` are mode `0600`, including when they already exist. Windows ignores Unix modes; the calls are best-effort there. |
| M4 | `apps/web/lib/local/mcp.ts` audit log | The log was a JSON array anyone who can write the folder can edit, with no way to see that it was edited. | Fixed. Each row carries the hash of the previous row. `audit_ok` on status is false when the chain does not match. Trading is not blocked by a broken log. |
| M5 | `apps/web/lib/local/mcp.ts` | Token symbols from the caller were stored and returned raw. A symbol can contain bidi overrides. | Fixed. Symbols go through `safeSymbol` before they are stored. |

## Low, or left as decided

| # | Location | Impact | Status |
|---|---|---|---|
| L1 | Jupiter route program | The official Jupiter program can call other programs. This build does not decode those inner calls. A hostile quote API could still ask Jupiter to pay a third party inside one Jupiter instruction. | Not fully removed. The quote must match the requested mints and min-out, the top-level instructions are checked (C1–C2), and only a transaction this app prepared can be sent (C4). |
| L2 | `real_prepare_swap` `guard_pass` / `risk_veto` | Those two flags still come from the window. The desktop process does not compute Guard itself. Caps, slippage, and the destination checks do not. | Open. A window that lies can claim Guard passed. It cannot lower the recorded caps or skip the transaction check. |
| L3 | `services/backend/api` `API_HOST` default `0.0.0.0` | The hosted paper API listens on every interface when `API_HOST` is unset. It refuses to start unless `TRADING_MODE=paper`. | Not changed. It is the paper server, not the local MCP. The local MCP HTTP server binds `127.0.0.1`. |
| L4 | Installer | The Windows installer is unsigned. | Not changed. That is an owner decision. The updater still requires the configured public key. |
| L5 | Limits | There is no ceiling on trade size, daily size, capital, or position count. | Not changed. Defaults stay 0.05 / 0.5 / 2 SOL and 3 positions. |
| L6 | `npm audit` on `apps/web` | 8 moderate findings, all in the ESLint toolchain (`minimatch` via `typescript-eslint`). Not in the running server. The suggested fix downgrades `eslint-config-next`. | Not changed. |
| L7 | `gitleaks` on history (277 commits) | 8 hits. They are test cursors, test token helpers, a fixture, and a script under the removed `apps/mobile` tree. No production key. | Not rewritten. History was not changed. |
| L8 | `cargo audit` | `cargo-audit` is not installed in this environment. | Not run. Desktop `cargo clippy --lib -D warnings` on Rust 1.90 is clean. |
